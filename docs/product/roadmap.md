# 路线图

状态：文档准备阶段；以下实现里程碑均未开始，没有已承诺日期。

本路线图根据项目讨论和最新 PRD 变更摘要整理，顺序及验收定义属于实施建议，待三份原始 PRD 核对后确认。范围以 [MVP 需求](../requirements/mvp.md) 为准；资料限制见 [资料来源](../requirements/sources.md)，技术方案建议见 [架构设计笔记](../architecture/design-notes.md)。

## M0：核对需求与实现边界

状态：文档准备。

整理项目型学习的跨会话接续闭环，核对原始 PRD，确定技术栈和首版交付形式。

验收定义：

- 明确哪些内容来自原始 PRD、变更摘要或讨论建议，待确认事项有单独记录。
- P0 的计划、任务、活动、接续和学习档案边界明确，有可用于实现和验证的流程。
- 确认技术栈及本地运行方式；在实际实现前不声明已有可运行产品。

## M1：完成项目学习接续闭环

状态：未开始。范围：P0。

围绕项目建立计划与任务，记录活动，让用户能够结束一次学习并在下一次继续。

验收定义：

- 会话开始时可读取当前目标、卡点、下一步和停止条件。
- 会话结束时可保存实际活动和证据，并关联相应项目与任务。
- 下一次会话能读取已保存的接续信息；建议、用户自述与实际发生的事实可区分。

## M2：建立独立学习档案入口

状态：未开始。范围：P0。

档案支持学习活动、用户自述自评、系统判断、学习偏好接续约定四类记录。

验收定义：

- 用户可通过独立入口查看四类记录；每条均可追溯来源、更新时间、修改者、关联对象和历史。
- 前端档案与 AI 使用同一份记录，更正后的有效内容在后续读取中一致。
- 用户确认表述准确不会被标为能力已验证；对评价提出异议不会直接触发改分。

## M3：验证更正、冲突与判断更新

状态：未开始。范围：P0。

补齐可信保存和派生判断的更新行为，作为首版可用性验收的一部分。

验收定义：

- 旧导入、晚到后台写入和重复请求均有验证案例，不能覆盖已生效的用户更正或重复生成活动。
- 保存回执清楚说明哪些变更已生效、哪些判断或结果仍待复核。
- 已确认失效的证据会触发相关判断复核；必要时判定可退回未判定，同时保留真实学习活动及历史。
- AI 辅助是否被允许，按具体能力标准处理；不采用统一允许或统一排除的判断。
- 更正期间产生的旧后台结果不能覆盖基于新依据得到的结果。

## 首版可选：事实周报

状态：未开始。来源：项目讨论建议，不作为已确认的 P0 硬需求。

在 P0 闭环完成且确认需要后，可提供简单的周度事实汇总。

建议验收定义：汇总可追溯到该周的真实活动与记录，区分已发生事实和后续计划；不自动推导缺少证据的能力提升或总分。

## 后续：概念关系与能力证据追踪

状态：未开始。优先级和范围待原始 PRD 核对。

逐步增加概念及一跳关系、能力与证据的关联查询，支持检查判断依据。

建议验收定义：

- 关系具有明确语义，能从概念查看一跳关联及来源。
- 能力判断可追溯到适用标准、标准版本和有效证据，也能查看相关异议及复核情况。
- 若提供完整度百分比，先定义版本化的领域基准、分母和计算规则，并单独表达未知；未知不计作 0。

## 当前范围约束

首版围绕项目学习与接续展开。不以前置建设通用个人操作系统、多 agent 系统或图数据库为里程碑；是否引入这些方案，需由后续明确需求和验证结果决定。
