# 架构设计笔记

状态：实现建议，尚未实现；技术栈未定。本文件依据可读取的项目讨论和最新 PRD 变更摘要整理，仍需与三份原始 PRD 核对。它不是正式数据契约；对象、字段和处理流程均为设计示例。

需求范围见 [MVP 需求](../requirements/mvp.md)，资料范围和证据限制见 [资料来源](../requirements/sources.md)。如与后续核对过的 PRD 冲突，应先更新需求，再调整这里的方案。

## 组织方式

建议先采用单一应用内的模块化服务和关系型存储，让计划、任务、活动、接续和学习档案围绕同一组对象协作。模块代表职责边界，不要求拆成独立部署的微服务。具体语言、框架、数据库和部署方式待选型。

| 建议模块 | 职责 |
| --- | --- |
| 项目与计划 | 保存学习目标、计划与任务，关联当前卡点和下一步 |
| 活动与证据 | 记录实际发生的学习活动及其证据，不把活动自动等同于掌握能力 |
| 会话接续 | 开始时读取目标、卡点、下一步、停止条件；结束时记录事实与证据 |
| 学习档案 | 提供独立入口，管理四类记录及其来源、修订和历史 |
| 系统判断 | 根据适用的能力标准和有效证据生成判断，维护依据与复核状态 |

首版不以前置建设通用个人操作系统、多 agent 编排或图数据库为目标。

## 关系化对象建议

以下对象用于讨论边界，名称和字段都需在实现前核对。

| 对象示例 | 建议关系与约束 |
| --- | --- |
| 项目、计划、任务 | 任务关联所属项目和计划；目标、卡点、下一步、停止条件可作为接续上下文 |
| 学习活动、证据 | 证据关联活动及其所支持的对象，保留来源；活动事实与判断结果分开存储 |
| 档案记录 | 区分学习活动、用户自述自评、系统判断、学习偏好接续约定四类；每条均可追溯来源、更新时间、修改者、关联对象和历史 |
| 档案修订 | 关联原记录，保存变更前后内容及修订关系；用户更正应能被追溯 |
| 系统判断及依据 | 关联证据、适用标准及其版本，记录判断状态与复核情况 |
| 接续记录 | 关联项目、任务和本次会话；结束记录应区分事实、证据与后续建议 |

档案记录与活动对象可以通过关系引用保持一致，避免手工维护两份事实。是否采用单表分类、分表或其他结构，留待实现设计。

前端档案和 AI 应通过同一组读取与写入服务使用同一份记录。AI 可以有检索索引或上下文缓存，但这些只能作为派生数据；读取时必须能判断是否落后于最新更正。

## 写入、更正与保存回执

建议使用下列行为约束，并在编码前明确冲突界面和重试规则：

1. 读取记录时一并取得版本；写入时提交预期版本，例如 `expected_version`。版本不匹配时返回冲突，让调用方基于最新内容重新处理，不能直接覆盖。
2. 用户更正与相应修订历史应一起保存。旧导入和晚到后台任务即使稍后到达，也不能仅凭到达顺序或外部时间戳覆盖该更正。
3. 为导入、后台写入和可重试请求设置幂等标识，例如 `request_id` 或“来源记录＋来源版本”。重复请求应返回既有结果，避免重复活动、修订或判断。幂等不能替代版本冲突检查。
4. 对历史更正存在冲突的导入，保留冲突信息并进入复核流程；具体合并规则待原 PRD 核对。
5. 保存回执分开说明已生效的记录变更，以及仍待复核或重新生成的系统结果。不能因为判断尚未更新而把已保存的更正显示成失败，也不能把保存成功显示成能力已验证。

例如，用户将某项自述更正为“只读过示例，尚未独立完成”后，基于旧版本启动的后台任务应被拒绝或转入复核；回执应明确该更正已生效，并标明相关判断的后续状态。以上字段与响应格式仅为示例。

## 更正后的失效与再生成

建议显式保存“判断依赖哪些证据、记录版本和能力标准”的关系。更正后先识别受影响的派生结果，标记其需要复核或更新，再基于当前有效记录重新生成。后台结果写回前仍须检查依赖版本；如果依据再次变化，旧结果不能成为当前结果。

处理规则需保留以下区别：

- 用户确认表述准确，只确认该表述；不能据此认定能力已经验证。
- 用户对自评或系统评价提出异议，应记录异议及处理状态，不能自动改分。
- 若证据被确认失效，相关判定可退回未判定，具体范围需按剩余有效证据与标准复核；真实发生的学习活动仍须保留。
- 是否允许 AI 辅助，要依具体能力标准判断，不能统一认定“使用 AI 即无效”或“允许 AI 即证明掌握”。

旧判断及其依据应保留历史，并与当前有效判断区分。任务重试失败或复核未完成时，应呈现实际状态。

## 后续扩展边界

概念及一跳关系、能力证据追踪可在核心闭环稳定后补充。关系数据可先通过关联表表达，出现明确查询需求后再评估其他存储方式。

能力百分比只有在领域基准、覆盖范围、计算规则和版本明确后才有可解释性；未知不能当作 0。首版不应先展示缺少基准的能力总分或能力完成率；任务进度须与能力判断分开展示。
