# ADR 0001：AI 协作与规格框架

状态：采用。日期：2026-11-13。范围：仓库工作方式，不涉及产品需求或应用技术栈。

## 背景

ThreadLine 仍在调研和完善需求。仓库需要支持 AI 长期接手，也让开发者直接阅读、审阅和修改；当前不应提前拆分需求或安排实施。

## 决策

采用 **OpenSpec + AGENTS.md + Git/PR + 自动检查**：

- 固定 `@fission-ai/openspec` 2.0.0，使用官方 `spec-driven` schema 与 CLI。
- 共享配置、中文文档与通用 AI 入口，不依赖特定模型或客户端命令包。
- 调研与需求草稿留在 `docs/`，具体变更以后进入 `openspec/changes/`。
- 主规格 `openspec/specs/` 表达已交付系统的当前行为，初始化保持为空。
- 实施进度由具体 change 的任务与验证证据表达，跨会话阶段由 `STATUS.md` 表达。

## 选择理由

[OpenSpec](https://github.com/Fission-AI/OpenSpec) 提供人可读的 Markdown、增量规格和归档流程，适合需求逐步明确后的持续迭代。纯 Markdown 清单缺少统一的变更生命周期；更完整的生成式工程模板会在当前阶段引入不必要的流程和文件。

不叠加第二套 spec 框架、不自定义 schema，也不预先生成能力列表。使用官方 CLI 获取当前格式说明，避免文档和工具约定分叉。

## 后果

- 首次开发需从已明确的需求创建 change，并编写新增行为的 delta；实现和验证后才同步主规格。
- `openspec status` 显示文档齐全，不证明实施完成。
- 空规格目录明确跳过校验；出现规格或活动 change 后启用严格校验。
- 工具升级单独提交并重新验证流程；应用运行时、数据库与部署平台以后另作决策。
