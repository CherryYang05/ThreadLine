# ThreadLine 领域能力追踪需求（草稿）

初版 2026-11-12 · 更新 2026-11-13

状态：草稿，调研与需求完善中。本文记录能力追踪的产品设想。

[ThreadLine 产品需求草稿](threadline.draft.md)描述了 GPT 录入、Site 保存执行与学习活动、Notion 保存长期知识的设想。本草稿补充基准、计划目标和基于证据的能力判断。配套文件是 [学习评估调研草稿](../research/learning-assessment.draft.md)、[评分与数据设计草稿](../design/scoring-and-data.draft.md)和 [RSI 基准示例草稿](../design/rsi-benchmark-example.draft.md)。

## 用户要完成的事

用户在 GPT 中说「系统学一下 RSI，把这轮目标定在领域基准的 40%」。GPT 读取已有计划、基准和可用证据，选择可以用本轮产物验证的标准，给出目标分、所需时间和结束条件。Site 在领域页展示目前的证据和能力分布，在计划页展示本轮承诺的验收项。下次开新对话时，GPT 从一个仍缺证据且影响本轮目标的步骤继续。

用户能在学习档案中查看当前生效的学习记录、自述、系统判断和学习约定，直接纠错并检查后续影响。档案复用原有对象与证据，能力分继续由本草稿及[评分与数据设计草稿](../design/scoring-and-data.draft.md)推导。用户也能打开知识页查「这个概念在哪些计划学过，能解释到什么程度，最近一次在哪种条件下验证过」。周报可以解释分数为什么变化，或为什么本周有推进但分数没有变化。

## 四个需要同时保留的数

| 指标 | 用户看到的样子 | 计算含义 |
| --- | --- | --- |
| 领域能力 | 已验证 20/100 · RSI v1 | 已有有效证据并达到预先定义标准的积分。展开显示尚未判定与已测未达标。 |
| 本轮计划 | 目标 40/100 · 按现有证据预计新增 20 分 | 已有能力与本轮验收通过后的条件结果。点开可看增加来自哪几个标准。 |
| 知识覆盖 | 接触 5/8 · 独立解释 3/8 | 分母为该基准选定的核心主题。同一主题在多个计划出现只计一次。 |
| 任务执行 | 完成 4/7 项 | 描述计划执行。任务勾选和阅读记录可触发收集证据，计分需要另行判定。 |

示例数字用于产品演示。没有已判定标准的领域首屏显示「未建立基线」，保留目标和未知范围。多个领域并列比较知识覆盖、能力维度和证据新鲜度，每张卡显示范围和基准版本。全局知识图可以持续扩展，领域覆盖的分母跟随已发布的基准版本。

## 100 分和 40 分如何产生

**100 分**由一个有边界的领域基准定义。以系统研究为例，应覆盖理解机制、实现或复现、测量与验证、独立研究设计、可审查地交流结果。以公开研究工作和评审要求校准难度，记录基准的适用范围、排除项和版本。一级能力由低到高可用「接触、能解释、能独立应用、能迁移验证、能独立研究」描述。未知单独显示。能力层级用于阅读能力剖面，积分由分项验收条件产生。

**40 分**是计划目标。规划先识别哪些标准已有证据，再列出需要补的标准、每项的验收产物和所需条件。用户已有证据可以纳入本轮起点，包括历史项目或合著成果。没有基线时，先显示「计划拟覆盖 40 分标准，增量待基线确认」。半小时的入门任务只承诺一项能兑现的产物。若目标超过时间或环境能支持的验收范围，GPT 给出可在本轮兑现的目标和达成 40 分所缺的后续产物。

允许两个 40 分方案的能力分布不同。计划需要明确这轮是为了读懂系统、跑通仿真，还是能解释误差。即便其他学习活动让领域总分超过 40，计划仍按原验收项检查是否达成。

## 使用流程

### 建计划与接续

1. GPT 读取领域基准、现有证据、当前计划与可用环境。已有成果按可用范围核对。找不到匹配基准时可起草一个范围和一版标准，交由用户确认后发布。
2. 草案列出分数、适用范围、投入假设、目标标准和验收任务。每个任务有完成条件与预期产物。按阶段或学习顺序组织，日期作为独立的可选排程。
3. 计划确认后固定基准版本和本轮承诺的标准。执行中可以修改计划，但保留原目标和修订原因。
4. 跨会话读取一个接续任务、一个结束条件、已有证据与暂缓的支线。发现新主题时，只有它影响当前验收才进入本轮主线。

### 从一次 GPT 记录留下证据

用户说「我跑通了基线，实测 20 ms，仿真 22 ms。还做了一张事件对齐表」。系统沿用活动写入，把任务完成和产物作为同批记录。GPT 提议产物支持的具体标准、所用帮助、本人贡献、证据位置，以及仍缺什么。只报告两个时延而缺少配置与测量边界时，活动可以保存，判定保留为证据不足。

待核验项集中在一处，用户只处理会改变评分的模糊项或争议项。允许选定的客观检查在可信执行记录下自动通过，研究级标准按规则要求复现、多份证据或可追溯的人类反馈。用户能看到是谁判断的，必要时补材料或纠正关联。

### 在学习档案查看和纠正能力记录

学习档案面向「系统如何理解我」，领域页面向「哪些标准已有证据」。两处引用相同的活动、主题观察、证据和判定。档案允许编辑活动事实、本人贡献、辅助条件、关联对象、学习自述与偏好；已验证分、独立解释覆盖及正式判定通过专门的证据复核流程更新，不提供直接改写系统分数的输入框。用户自评单独保存。

| 操作 | 判定和分数的处理 | 下一次学习如何使用 |
| --- | --- | --- |
| 确认“记录准确”或填写自评 | 确认表述及来源，不升级为能力通过或独立解释证据。明确自述可按原规则支持接触观察。 | 带上用户来源，避免把自评改写为客观验证。 |
| 对当前能力提出异议，如“我现在没把握” | 保留有效旧判定及 V/F/U，增加待复核标记。有争议时显示“按现有判定 20/100 · 其中 5 分待复核”等带限定的文案，示例数来自被标记标准的权重。 | 同时返回原验证条件与最新自述；安排适当复测或基础练习，不无条件断言已掌握。 |
| 更正证据事实，如“作品并非我独立完成” | 检查证据归属、帮助条件和原标准；错误前提使当前判定失效时撤销。另有满足门槛的有效支持则保留结果，否则进入未判定 U。 | 撤销结果不再支撑能力结论；保留真实学习活动并说明待补证据。 |
| 完成符合条件的正式复测 | 按原规则接受新的通过或未通过判定；明确未通过才进入 F。 | 按新结果调整接续，历史达成事件仍可查。 |

“确认档案内容”与“审核能力判定”使用不同操作；后者必须检查具体标准、证据位置、允许帮助和来源门槛。用户编辑一句“已经掌握”也不能直接加分。较弱或不同情境的证据不覆盖有效旧判定，但已确认的事实错误不能以此为由继续保留错误判定。

更正后按依赖关系更新主题覆盖、当前能力结果及后续建议；无需重算无关领域。自述和当前卡点可以立即影响接续难度，任务完成状态与既有排程不随之自动改写。旧周报保留当时快照，标注来源已更正，可生成修订版。

普通记录停止用于 AI 后退出个性化上下文与推荐，已有独立评分证据的保留情况必须说清。撤回或删除必要评分证据时检查依赖判定，无其他有效支持则撤销至 U。历史快照不能代替当前证据；永久删除沿用[产品需求草稿](threadline.draft.md)及[评分与数据设计草稿](../design/scoring-and-data.draft.md)的清除和脱敏规则。

### 在知识网和周报回看

概念页先显示一句定义、最近证据和当前层级，再展开来源与关系。图谱默认只显示一跳，另有关系列表。边用于导航和提示可能相关的证据。跨领域的同名能力，例如「构造公平基线」，可共用能力标识，必须检查证据是否适合新的标准与情境。

周报写明同版本期初和期末、哪些标准新通过、哪些复测暴露缺口、哪些变化来自修订或纠错，点击回到活动和产物。时间越久可触发建议复测，不触发分数变化。相近条件下的正式复测可更新当前判定，历史成绩与证据同时可查。

## 页面层级

| 位置 | 首屏 | 展开后 |
| --- | --- | --- |
| 今日 | 一个接续任务及完成条件。 | 可进入相关计划与证据。 |
| 计划 | 目标、结束条件、一个下一步。能力分仅一行「已验证 20/100 · 本轮目标 40/100」。 | 逐项看验收产物、预计增量、阶段、覆盖和分数说明。 |
| 学习档案 | 当前学习概况、有效记录、最近更正和待核验提示。 | 查来源、编辑事实或自述、对判断提异议、查看影响与历史；连接原概念和领域标准。 |
| 领域 | 显示范围、版本、已验证分与分维度进度；有争议时标明待复核范围。 | 切换覆盖／能力，查看每项标准的证据、判定和复测，与档案共用数据。 |
| 知识 | 搜索与当前概念的证据摘要。 | 关系、计划、复测、Notion 链接和纠错入口。 |
| 周报 | 本周变化与主要成果。 | 区分补录、复测、撤销和基准升级，打开原始证据。 |

沿用原 PRD 的阅读优先和单一主操作。用圆角卡片组织领域和计划，轻阴影用于浮起的详情。进度卡显示清楚的文本分母，颜色辅助识别，移动端可以逐项展开。任务勾选原位即时反馈。评分证据的异步更新可在相应区域回读，任务列表行高稳定。待审和编辑入口放在详情，保留键盘访问。

## 分期交付

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| P0 执行与接续 | 沿用总 PRD 的活动、计划、学习档案、GPT 读写和周报。保留来源、任务、本人角色和学习约定，不依赖完整评分。 | GPT 写一次活动，档案能找到原记录。纠错后新会话使用新状态；确认表述不等于能力通过，旧来源不恢复错误。 |
| P1 能力追踪 | 先用 RSI 一个领域上线基准、40 分计划、证据判定、快照与周报来源。学习档案、领域和知识页能回查同一证据及异议。 | 用 [RSI 基准示例草稿](../design/rsi-benchmark-example.draft.md)走通原有评分，用[评分与数据设计草稿](../design/scoring-and-data.draft.md)中的档案场景区分表述确认、能力异议、证据纠错和正式复测。第二个计划复用证据不重复加分。 |
| P2 跨领域扩展 | 加入第二领域、带适用条件的共用能力、外部反馈与复测。 | 验证跨领域可发现证据、确认归属、独立判定，并且旧周报仍可解释。 |

首轮只要求 GPT 默认录入、用户能核查与纠正，保留人工评估和可信机器检查。准备专门的研究级标定案例后，再讨论自动判读上限和评估一致性。新项目从脱敏示例起步，既有站点继续用于短期维护。旧数据是否迁移以及迁移范围由新站验收后决定。
