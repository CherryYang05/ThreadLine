# ThreadLine 产品需求规格

初版 2026-11-11 · 更新 2026-11-13 · 供 Codex 云端开发与 ChatGPT Site 实施使用

本次补充学习档案的查看、编辑、纠错与后续生效规则。领域基准和能力评估见 [02 领域能力追踪 PRD](02-research-maturity-prd.md)，评分口径及一致性见 [03 评分与数据契约](03-scoring-and-data-spec.md)。

## 1. 要解决的问题

你每天在 GPT 里讨论工作、拆学习任务、读资料和做复盘。对话可以带你深入一个问题，但结束后，计划、实际做过的事、证据和下一步容易散落在不同会话。开下一轮时，你还得重述背景。做周报时，又得重新翻聊天。几个学习计划都讲到 KV Cache 时，也很难看出哪些已学过、哪些只在聊天里提过。

新 Site 要做到 **一次在 GPT 里表达，两处可继续使用**。执行端可以回答「今天做什么、实际做了什么、这周推进了什么」。记忆端可以回答「以前在哪学过、它和哪些概念有关、我最后一次证明自己会用是什么时候」。两端引用同一条记录。学习档案集中展示系统保存的学习经历、自述、能力判断和学习约定；你可以查看来源、修改和纠正，再从任意已连接该插件的 GPT 会话读回最新有效记录。纠错应影响下一次学习接续与建议。

这是一套以你为首位用户的私人工作台。现有 Bearguin Site 继续短期维护。新 Work 新建独立 Site、存储和连接。初期用测试数据跑通，再按需复制选定计划和记录。

相关产品已经覆盖了许多组成部分。这里值得验证的组合，是**用同一个 GPT 入口完成捕获、接续和纠正，让一次学习同时推进任务、留下证据，并在以后其他计划中被找回**。最先检验它能否省掉你重讲背景和重新整理周报的时间。

### 学习档案的设计依据

开放学习者模型研究讨论了向学习者展示判断及其证据，并通过直接编辑、补充证据或协商维护记录；分歧未解决时，可以分别保留系统判断与用户自评。[Bull，2016](https://link.springer.com/article/10.1186/s41039-016-0035-3) 的这些设计区分适合用于学习档案。交互上采用方便纠错、解释依据及说明操作后果的原则，见 [Microsoft 人机 AI 交互指南 G9、G11、G16](https://www.microsoft.com/en-us/research/blog/guidelines-for-human-ai-interaction-design/)。它们提供设计依据；ThreadLine 是否减少接续错误与维护负担，仍需用实际试用验证。

## 3. 三个系统各自负责什么

| 系统 | 权威数据与职责 | 使用方式 |
| --- | --- | --- |
| GPT | 从当前可读的对话、链接或文件中提取记录，提出计划、关联、总结与复习题。收到后端回执才说写入成功。 | 你的默认录入口。理解意图、读现状、处理歧义、提交结构化记录。 |
| 新 Site | 目标、项目、学习计划、单元、任务、活动事实、概念和关系、掌握证据、学习自述与偏好、周报快照。 | 通过学习档案集中查看、确认、纠错和管理；支持导出。GPT 与网页操作同一份数据。 |
| Notion | 长篇笔记、稳定知识、资料与成果文档。 | 从 Site 跳转，或在用户指定目标库后由 GPT 写入。Site 保留 Notion 页面 ID、链接和同步状态。 |

Notion 页面可关联多个概念和计划。Site 保留足以继续学习的简短摘要和状态，避免因 Notion 暂时不可用而阻断日常执行。一个字段只有一个权威来源。同步只传需要共享的字段，遇到失败单独重试。首版可先绑定已有页面链接，再验证自动写入。

## 4. 主要流程

### A. 创建学习计划

例「我想用两周系统学习 RSI 训练仿真，每天 3 小时，最终能解释候选配置怎样变成仿真结果，并做一组对照实验。」

1. GPT 先检索同名计划、已有知识点和相关项目，提示可以复用的内容。
2. 草案包含目标、范围、总时间、验收产物、可调整的学习单元，以及每个任务的预计时间、完成标准和来源。单元不限于固定天数，任务可跨日期改期。
3. 用户确认后一次保存，返回计划链接和已创建的条目数。计划可以设为当前主线，单独记录下一步和停止条件。
4. 后续改期保留实际发生和原计划日期。已有目标和历史证据留在原对象。拆分或合并计划也保留来源与交叉引用。

项目可关联多个学习计划。比如 RSI 仿真项目可关联训练通信校准、性能建模和专利技术交底，首版项目只需目标、状态、下个里程碑与关联活动。阅读记录可挂论文、技术博客或 Notion 链接，标记待读、已读或做过笔记，链接到概念和计划。

### B. 记录今天实际做了什么

例「今天花 40 分钟跑通了 RSI baseline，报告在这里。又看了 Prefix Caching，能解释命中逻辑，没写过实现。先把 KV 传输优化放到后面。」

GPT 将消息拆成实际活动、相关任务结果、知识证据和暂缓事项。仅在用户明确表达完成，且匹配到具体任务时更新任务状态。预计时间只来自计划，实际时间只来自用户或可引用的记录。没有时间就保留空值。对「昨天」按用户时区解析并回显具体日期，后补记录进入事情实际发生的那周。

明确的新增日志和完成指令可以直接提交，并回执「记录了哪几条、关联了什么、还有哪项待确认」。不确定的对象、推断出来的知识关系和计划批量改动进入一个草稿，用户可逐项编辑或确认。提交超时先查询批次结果，安全重试，重复提交返回已有结果。两次内容相似但发生时间不同的练习保留为两次活动。

可以给指定的学习对话配置结束时主动询问是否沉淀。用户授权范围内的主动采集、批量导入和定时运行分别设计。首版的自动化目标是用户说一次，GPT 完成结构化写入并给出回执。

### C. 跨会话继续，并避免递归学习

新会话中说「继续 AI Infra 学习」，GPT 获取当前计划的目标、最近确认结果、当前卡点、一个下一步、结束条件和已暂缓支线。默认依据已确认的手动指定或学习单元顺序恢复，必要时向用户说明推荐依据。

遇到新分支时先判断它是否阻塞当前产物。比如为了解释 Prefix Caching 命中，搞清 Block 匹配可能需要进入主线。LM Head 实现若不影响产物，可以记录为「暂缓，等研究推理计算路径时再开」。支线卡包含问题、暂缓原因、重启条件和来源。达到结束条件后提示收尾并记录结果。用户明确切换目标时允许调整主线。

### D. 看知识网与复习

知识页从搜索或当前计划进入。选中一个概念时展示一句话定义、来源、关联计划和任务、最近证据、相关概念，以及带来源的关系。默认一跳，按需扩展或筛选。每张图有等价的关系列表，可键盘使用，也适合手机。全局图适合作为浏览入口的增强项。

示例学习顺序可以是「KV Cache → PagedAttention → Prefix Caching → Disaggregated Serving」。技术关系单独记录，保留实现和版本范围。

| 起点 | 关系 | 终点 | 来源 |
| --- | --- | --- | --- |
| PagedAttention | 分页管理 | KV Cache | [PagedAttention 论文](https://arxiv.org/abs/2309.06180) |
| Prefix Caching | 复用共享前缀的缓存 | KV Cache | [vLLM 设计文档](https://docs.vllm.ai/en/stable/design/prefix_caching/) |
| Prefill/Decode 分离 | 阶段之间传输 | KV Cache | [DistServe OSDI 论文](https://www.usenix.org/conference/osdi24/presentation/zhong-yinmin) |

比如「LLM 原理补充」和「Serving 性能建模」都关联同一个 KV Cache 节点。两个计划可以各自记录学到哪，概念页汇集相关证据。关系可标为前置、实现、使用、比较或相关，必须能打开出处。GPT 建议的边可见地标成待核验。近似概念只提示可能重复，合并后保留旧名称和历史链接。

概念页分别呈现三件事：

- **掌握证据**：未验证、接触过、能独立解释、能独立应用。每次自述、自测或产物都可溯源，并记录是否用了提示。
- **复习状态**：最近验证日期、是否待复习、最近一次复测结果。长期未测只表示证据较旧。若先前能独立回答，后来在相近条件下回忆失败，可显示「这次未能回忆」并保留两次记录。用户也可以补充自述。
- **任务状态**：待办、进行中、完成、延期或取消。完成阅读任务可以留下「接触过」记录，独立掌握需要另外的证据。

### E. 生成周报和趋势

Site 中点击「生成周报」，选定一周后立即汇总。默认周一至周日，使用 Asia/Shanghai；在周中生成则标注截至时间。每条事实链接到活动或产物，显示计划与实际、主要成果、复习或卡点、待接续工作。月度或自定义区间复用同一套口径。

| 指标 | 口径 |
| --- | --- |
| 完成任务 | 区间内完成且生成时仍有效的任务，按任务去重。重开保留历史并可单独列出。 |
| 实际投入 | 区间内有效活动填写的实际分钟之和。可按计划或项目查看，用时缺失单列，不以预计值补齐。 |
| 学习成果 | 区分接触、独立解释与独立应用，列出证据。概念数和读过的页面数不作为能力评分。 |
| 计划变化 | 改期、取消和新增分别列出，可回看原计划。未记录的日期标为无记录。 |

首版可以在 Site 一键生成可读的统计和模板摘要，结果可保存、复制 Markdown 和查看来源。后续接入 GPT 叙事时，只把选定周期的事实包交给模型，正文中保留证据引用。数字由查询计算，生成失败仍可查看事实表。补录或纠错后可以生成新版本，已保存的旧周报可回查，周报生成不会触发任务改写。

### F. 查看并纠正学习档案

**学习档案是 ThreadLine 已保存学习记录的统一查看与纠错入口。** 用户能知道系统记了什么、依据哪里、何时更新、会怎样影响后续学习。范围限于已通过明确指令、授权流程或导入存入 ThreadLine 的数据；页面不声称展示模型内部状态、ChatGPT 全部记忆或未接入的历史对话。

首屏按当前项目或学习领域回答「正在学什么、学过什么、目前会什么或卡在哪里、下一步及学习约定是什么」。目标与任务引用现有计划，能力结论引用现有证据和判定。凡是 ThreadLine 长期保存并用于个性化学习的记录，都须能在档案或其直达详情中查看和纠正。记录默认折叠为简短描述，可按领域、计划、知识点、类型和状态搜索筛选；有待核验项时显示数量，无需逐条确认每次普通活动。

| 内容类型 | 示例 | 展示与编辑规则 |
| --- | --- | --- |
| 已记录的学习活动 | 学习过 PP 与 microbatch，完成一次练习。 | 展示实际发生时间与来源。可更正活动描述、日期、对象关联及完成情况；完成活动不自动表示掌握。 |
| 用户自述与自评 | 理解 PP 的作用，尚不能独立画出 1F1B 时序。 | 标注用户自述，可直接编辑、补充；与系统证据判定并列保留。 |
| 系统的学习判断 | 在指定条件下能独立解释；某项仍缺验证。 | 展示证据、适用条件及待核验或争议状态。可纠正提取错误、提出异议、补证据或发起复测。已验证分按 02、03 的规则生成。 |
| 学习偏好与接续约定 | 课后题需要更复杂；先学完当前主线再补 MLP。 | 可直接修改或停用。标明全局、领域或计划范围；具体范围内的明确约定优先于全局默认。 |

每条记录展示来源类型、最近修改时间和当前使用状态。展开后可查看来源位置或必要摘录、关联对象、修改者与修改历史；来源无法重新打开时说明现有依据，不伪造对话链接。界面区分「用户确认表述准确」「系统建议」「已通过能力验证」，不用一个“已确认”标签混在一起。没有验证结果的内容显示未验证，不补造掌握度百分比。

**更正流程。** 用户点开记录即可改可编辑字段，也能在 GPT 中说「这条记错了，改成……」。两种入口使用同一更新逻辑。保存后显示新记录、实际生效范围和受影响结果；普通纠错只需一次保存。原始对话、代码或测验记录不被改写，纠错以新版本指向旧记录。支持查看历史和撤销最近一次非删除修改；撤销也生成新版本，不能覆盖期间发生的更新。

例如系统概括「已掌握流水线并行」，用户改为「了解 PP 的目的，尚不能独立推演 1F1B 调度」。新的学习接续必须带上这项自述和未解决的分歧，安排相应练习；真实发生过的 PP 学习活动仍保留。没有合格证据的 AI 概括不能继续充当已掌握结论。已有正式通过判定时，异议先标为待复核并保留原验证条件；明确纠正了本人贡献、辅助条件等事实且使判定依据失效时，才撤销受影响判定。详细计分规则见 02、03。

**更正后的生效规则。** 当前档案、概念详情、接续上下文、后续推荐与新生成摘要必须引用最新有效版本。更改偏好无需重算能力；更改证据或判定则沿关联更新受影响结果。摘要或推荐尚在刷新时显示待更新，不把旧结果冒充为最新。已经保存的历史周报保留当时快照，并标注关联来源已更正；需要时生成修订版。更正不会自动改写已确认的任务排程。

用户更正的内容不能被旧对话重导入、同一来源重提取或旧版后台任务静默覆盖。来自新独立证据的变化可以提出复核建议；涉及用户明确约定或存在冲突时，先展示差异和依据。可通过新增证据更新能力，不能把纠错变成永久冻结。

**停用与删除。** 「停止用于 AI」使该条记录及其派生表述退出后续个性化上下文和推荐，本人仍可在停用记录中查看。普通描述的停用不等于撤回独立评分证据；证据条目提供明确的「撤回证据」操作并显示评分影响。永久删除须清除指定正文、历史及受影响的敏感派生内容，遵守第 6 节的删除规则。为阻止同一旧来源重新生成被删除条目，仅保留必要的排除标识，不借审计历史保留已删除正文；解除排除需用户明确操作。

首版做好记录列表、来源详情、直接编辑、异议、历史与生效回执。复杂全局知识图、整段聊天归档和自动人格画像不作为该功能的前置条件。档案管理应能在一次日常纠错中完成，避免新增一套每日维护表单。

沿用旧站验证过的克制做法。顶栏用明确的动作或对象命名，首屏一个主操作；阅读默认简洁，详情有足够宽度和可读行距，编辑和删除可直接找到。任务勾选立即反馈，同一列表中原位展示，不自动移动、不改变高度；保存失败恢复并提示。空状态、同步中、写入失败、同名冲突和无权限时均有可读提示。第一版兼顾桌面与手机；图谱不可用时关系列表仍可浏览。

## 6. 最小数据与 GPT 工具

活动是事实时间线。任务和概念的当前状态可以直接查询，重要变更在同一事务内留下历史。首版用关系表表达图谱，并按概念和计划查询邻居；个人规模无需先部署独立图数据库。学习档案复用这些权威对象，通过对象 ID 和版本汇总展示；生成摘要只做可重建视图。已有活动、任务、证据和判定不复制出第二套可独立修改的状态。

| 对象 | 最小字段和关联 |
| --- | --- |
| 目标 / 项目 | 标题、状态、完成条件或里程碑。项目可关联多个计划、任务和活动。 |
| 学习计划 / 单元 / 任务 | 稳定 ID、归属、顺序、状态、原计划日期与当前日期、预计时长、完成标准、结果。计划另有目标、接续点、当前卡点、停止条件与暂缓清单。 |
| 活动 | 类型、实际发生时间、录入时间、标题/摘要、实际分钟（可空）、来源、关联对象、幂等键、确认状态。纠错指向原记录。 |
| 知识点 / 关系 | 标准名称、别名、简述。边包含方向、关系类型、适用范围、来源和核验状态。 |
| 证据 / 复习 | 用户自述、问题与回答摘要、代码或文档链接、结果、是否辅助、时间、相关知识点和任务。保留用于比较的历史证据。 |
| 学习自述 / 偏好 | 稳定 ID、内容、作者、适用范围、关联概念或计划、来源、使用状态与版本。 |
| 档案视图 / 修订 | 关联的对象类型、对象 ID 与版本；修订记录保存修改者、时间、修改范围、替代或排除关系，以及受影响派生项。 |
| 周报 | 周期、时区、计算版本、来源记录 ID、摘要、生成时间、修订版本。 |

**来源模型**可引用对话定位、用户提交的摘录、文章链接、Notion 页面、文件或代码产物。记录来源是否可重新访问。对话定位不可得时保留用户提供的摘要和时间，链接仅在能取得且用户可打开时附上。默认只存结构化记录和必要摘录，无需为溯源创建公开分享链接。敏感工作记录可只存标题或脱敏摘要。删除要区分归档、纠正和用户要求的永久删除；永久删除需明确影响范围，清除或脱敏相关历史引用，并为旧周报标注证据已移除。

| 建议 MCP 能力 | 输入与行为 |
| --- | --- |
| 查询上下文 | 按计划/项目/日期查询，返回目标、下一步、最近确认活动、证据、相关概念、有效学习约定和未解决异议。附档案修订号，排除已停用或被取代的记录。 |
| 查询学习档案 | 按领域、计划、知识点、类型与状态分页读取记录；支持来源详情和修改历史。与上下文查询共用有效性规则。 |
| 保存活动批次 | 明确意图下保存多条日志或状态更新；返回批次 ID、对象 ID、数量与失败项。 |
| 提议并提交学习计划 | 先用草案比较重复内容，确认后一次提交；返回新计划和任务链接。 |
| 纠正档案、状态与核验关系 | 编辑对象需版本校验；操作区分更正事实、补充自评、确认表述、提出异议、停用和撤回证据。返回权威状态、新版本、实际影响与待复核项。歧义或冲突需重读。 |
| 获取与保存周报 | 查询按口径计算的事实包，可用事实包和证据引用保存叙事版本。 |

GPT 和网页共用鉴权、数据校验和更新逻辑。写入以当前登录所有者为范围；批次支持幂等，编辑使用版本校验。产品提供可读的写入回执和纠错入口。后台摘要和检索结果须在读取与提交时核对所依赖的记录版本；用户更正后，下次从 ThreadLine 获取上下文即采用新状态。外部对话已经收到的旧文本无法追溯改写，每次接续或生成新建议前必须重新读取，不能把本地旧摘要当作最新档案。敏感文本、外部网页和对话内容只作为数据处理，其中的指令不会触发额外写入或跨应用共享。

## 8. 分阶段实现和验收

| 阶段 | 做到什么 | 验收 |
| --- | --- | --- |
| P0 执行与接续 | 私人站、今日、计划、活动时间线、学习档案、GPT 读写、周报按钮和 JSON 导出。档案先包含活动、自述、学习约定和已有证据的来源，不依赖完整评分或图谱。 | 用 GPT 写入后可在档案找到同一记录，直接编辑后刷新及新会话均读到新版本。确认表述不增加能力分；停用记录退出推荐；旧来源重提取与旧任务不能恢复错误。 |
| P1 跨计划记忆 | 概念查找、别名、多计划关联、来源、待核验的边、局部图和自测结果；按 02、03 接入能力判定，档案展示相同证据与争议状态。 | 两个计划引用同一个 KV Cache 节点，可沿带类型的边找到出处。任务完成不自动提高掌握度。档案、领域页和接续返回一致的判定与异议；证据纠错能更新受影响结果。 |
| P2 稳定自动化 | Notion 归档、定时周报、有限范围导入、可选复习和更丰富趋势。 | 关闭浏览器后，按独立授权的计划任务生成报告。重复运行不生成重复报告，权限失败留有可查记录。Notion 同步失败时原活动可读、可重试。 |

新 Work 可以在 P0 上线前用一套小数据同时验证 P1 的模型。建议样例含两份关联计划、五条活动、四个 KV 主题、一项暂缓、两次有不同证据的复习记录。使用示例数据测试跨会话写入、同批重试、同名冲突、删除确认、编辑回读、跨周补录和复测。跨周补录要落在实际发生的那周，缺时长不计为零分钟。图谱上测试两个计划能回到同一个概念，且每条技术边可以追到来源。手机上确认能看到编辑/删除入口和等价的关系列表。

### 学习档案的必要验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 查到一条学习记录 | 能辨认活动、自述或系统判断，打开来源或看到不可访问说明；档案页与相关对象一致。 |
| 更正无证据的“已掌握”概括 | 新会话采用新自述并保留尚缺验证之处，原活动不被自动取消；错误概括不再作为有效结论。 |
| 对有效判定说“我现在没把握” | 保存异议，界面显示原验证条件及待复核；不直接增减分，也不继续无条件断言已掌握。 |
| 更正“独立完成”为“按 AI 步骤照做” | 按标准重查依据；不满足条件且无其他有效支持时撤销当前判定，归为未判定，不记作复测失败。 |
| 确认档案描述准确 | 不自动产生通过判定或独立解释证据。 |
| 同时编辑或后台使用旧版本提交 | 拒绝过期写入，返回当前状态；旧结果不能覆盖用户更正。 |
| 重新提取同一段旧对话 | 已被更正、停用或删除的结论不会重新成为有效记录；新独立证据另行复核。 |
| 停用、撤回证据或永久删除 | 回执区分影响；旧上下文与派生结果不能绕过排除规则，删除正文不会留在历史详情里。 |

个人试用可以用连续两周观察。建议记录每周通过 GPT 写入的活动数、重复或漏记次数、跨会话恢复是否能一步定位下一步、生成周报后需要人工纠正的条数，以及支线暂缓是否减少了本轮中断。同时记录发现错误到完成更正的操作数、更正后再次出现同一错误的次数、无依据的能力判断数，以及每周档案维护时间。上线验收要求固定测试集中已更正旧结论不回流；长期学习收益另行观察。现阶段还没有实测基线。

## 9. 交给新 Work 的建站指令

> 使用这份规格在 Codex 云端开发 ThreadLine，并创建全新的私人 ChatGPT Site，现有 Bearguin 学习站保持短期维护。以 GPT 作为默认录入界面，Site 保存活动事实、学习计划和可追溯周报，Notion 保存长期文档。先验证 P0 的完整闭环和学习档案：展示来源、编辑纠错、区别自述与判定、让新会话采用更正，并防止旧来源恢复错误；再用两份学习计划和 KV Cache 示例实现 P1 的概念详情、关系和证据。以私人、可纠错、可导出为默认。工作或专利相关示例用公开或虚构数据。使用测试数据完成跨会话读写、幂等、编辑回读、周报口径、归档删除和响应式验收。模型生成、定时执行、Notion 无人值守写入分别验证，按结果实现。新站通过验收后，再决定从旧站复制哪些记录。
