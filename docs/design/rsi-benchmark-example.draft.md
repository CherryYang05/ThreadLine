配合 [领域能力追踪需求草稿](../prd/domain-assessment.draft.md)和 [评分与数据设计草稿](scoring-and-data.draft.md)讨论。本文件提出量表和验收数据示例，可供未来实现阶段设计测试时参考。

## 基准范围

**LLM 训练性能仿真与实测校准 v1**。适用于分布式训练中的 Step、算子与通信事件、配置和调度、计算／通信／显存建模及其验证。用公开框架与合成 trace 演示，不需要导入内部工作资料。LLM 推理、PD 分离、模型收敛理论和硬件物理设计可以在知识网里关联，按需建立独立基准。样例只定义训练性能仿真这一范围。

成熟工作示例是能独立提出有价值且可证伪的训练仿真问题，建立可解释的仿真或校准方法，在匹配与留出配置下进行验证，完成误差分析并公开或向授权同行提交可复查的产物与论证。可参考 SimAI 的公开系统工作和 SOSP 对研究问题、实现、证据和结论的要求。[SimAI，NSDI 2025](https://www.usenix.org/conference/nsdi25/presentation/wang-xizheng-simai) · [SOSP 2026](https://www.sigops.org/s/conferences/sosp/2026/cfp.html)

这是首版设计样例。分值和验收项由产品选择，未根据研究者样本标定。下文的 20/100 是测试数据。Cherry 可以用已有仿真、校准和系统实验产物建立基线。已有成果只有符合这一版具体标准和个人角色要求时才计分。

## 能力量表

每项 5 分，共 20 项。★ 表示这一轮的目标标准，共 8 项、40 分。每个标记都指向可观察的验收产物。

| 维度 | 满分 | 本轮 | 本轮标准 |
| --- | ---: | ---: | --- |
| A. 训练 Step 与 trace | 20 | 10 | A1、A2 |
| B. 并行切分与调度 | 20 | 5 | B1 |
| C. 计算、通信与显存建模 | 25 | 10 | C1、C2 |
| D. 实测校准与验证 | 25 | 10 | D1、D2 |
| E. 研究问题、复现与交流 | 10 | 5 | E1 |
| 合计 | 100 | 40 | 8 项 |

| ID | 达标表现与验收 |
| --- | --- |
| A1 ★ | 给指定配置的一次训练 Step 标出 forward、backward 和参数更新，用事件定位、起止边界及自己的口头或文字解释验收。说明该配置下梯度同步和计算的重叠位置。 |
| A2 ★ | 将关键算子与通信事件对应到 rank，说明至少一条顺序依赖或重叠关系，交付标注 trace 与时序解释。 |
| A3 | 以映射表对齐模型源码和原始算子图。交付名称、数量、shape 与顺序，说明高开销算子的覆盖范围，给出未匹配项及原因。 |
| A4 | 区分模型定义与框架运行新增事件。针对一个未用于教学的框架配置或优化器，在预测后对照 trace，定位额外算子及影响。 |
| B1 ★ | 对固定 DP／TP／PP 配置推导局部 shape 和关键 collective 的触发条件，交付推导与实测事件对照，说明至少一个因并行产生的差异。 |
| B2 | 为给定流水配置绘出 microbatch 时序，解释至少一段 bubble，并用 trace 核对。 |
| B3 | 对比两种受支持的流水调度。在固定模型、batch 和测量边界下解释重叠变化，提供关键事件对照。 |
| B4 | 对一个新布局或并行配置预先给出瓶颈或性能排序，然后验证，记录错误排序或不确定性的来源。 |
| C1 ★ | 用 profiler 对照两个 shape 的计算算子耗时。说明采样、同步、重复运行及误差口径，交付输入和实测数据。 |
| C2 ★ | 在固定拓扑和消息大小下，对照一次 collective 的仿真与实测，说明参与 rank、数据量和计时边界。 |
| C3 | 核对参数、梯度、优化器状态和激活的生命周期与峰值，说明显存统计的边界。给出估算、测量和主要差额。 |
| C4 | 对照融合或框架新增算子，解释至少一处对计算、访存或调度开销的影响，用受控实验支持。 |
| C5 | 对未用于拟合的 shape 或消息大小评估模型，给出误差分布及适用边界。记录独立留出条件，保留原拟合输入。 |
| D1 ★ | 在一份配置中核对模型、框架、并行、硬件与 Step 边界，交付实测和仿真对照表，包括 Step 时延、绝对与相对误差以及至少一个事件层检查。 |
| D2 ★ | 从配对 trace 定位一个主要误差来源，改变一个因素进行复查，交付假设、对照结果与仍未解释的误差。 |
| D3 | 预先冻结拟合条件和留出配置，验证校准能否迁移。记录未达标案例、采样误差和可以外推的范围。 |
| D4 | 对选定的校准方法做基线和消融，比较参数或组成模型的影响，解释结论对测量噪声和选择的敏感性。 |
| D5 | 用一个此前未用于校准的工作负载或拓扑评估仿真决策，检查优化方案的排序是否与实测一致，报告反例。 |
| E1 ★ | 交付一份可重跑的基线包，含命令、版本、配置、原始数据或脱敏替代、期望输出与边界。用一次干净环境复跑或明确记录的独立复跑验收。 |
| E2 | 独立提出有依据的研究问题，写清与前作的差别，提供可复现的验证和论文式论证。提交本人贡献与可追溯的领域同行反馈或答辩记录，并说明至少一处基于质疑作出的修订。 |

A3 至 D5 可分阶段获取，证据中的依赖关系单独保存。预先约定的环境与误差标准适用于该实验。已公开论文的对齐数字可作参照，项目阈值应结合采样噪声和目标单独设置。若要展示「能独立研究」里程碑，本样例将 D3、D4、D5、E2 作为必要项。复跑记录可供多个标准引用，每条仍要检查各自的要求。

## 阶段和停止条件

| 阶段 | 操作与产物 | 对应标准 |
| --- | --- | --- |
| 1. 读懂一次 Step | 从一个公开训练样例找到训练 Step 输入和 trace 边界，标注前后向、同步、更新及相关 rank。能用自己的话指出一个依赖。 | A1、A2 |
| 2. 对齐配置与组件 | 推导固定并行配置下的局部 shape，定位 compute 与 collective。在可获得实测时完成两种 shape 和一种固定通信条件的对照。 | B1、C1、C2 |
| 3. 实测校准和复跑 | 对齐版本与边界，给出 Step 和事件层对照，检验一个误差假设，并保留一套可复跑的基线包。 | D1、D2、E1 |

最初的 30 分钟只要求产出一张训练 Step 事件草图和一个待查问题，用来定位阶段 1 的验收入口。若缺少可用 profiling、训练环境或可比较的 trace，把对应标准列为待验证。可以用合成数据演练，标记为演示数据，不将演练结果记为真实系统的校准能力。学习投入随配置、运行条件和已有基线估计，计划发布前应列出这些条件。

核心主题固定为 8 个。训练 Step、算子图与事件、并行与调度、计算建模、通信建模、显存建模、实测校准、可复现研究。每个主题在任何计划中出现都保留来源。技术图谱可继续添加「梯度同步」「TP」「collective」等具体节点，通过关系表连接，不改变这 8 个主题。
